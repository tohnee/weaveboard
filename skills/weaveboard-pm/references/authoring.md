# 看板数据编写规范（PM 语义）

字段合法性看 `schema.md`；这份规范决定生成的看板**专业不专业**。

## 任务与依赖

- **里程碑管节点，任务管交付**：M1/M2 是状态翻转点（"契约冻结""灰度上线"），不是一个工作包。每个里程碑 2–4 个子任务。
- **依赖只建真实的**：任务 A 不做完 B 无法开始才建 FS。组织关系（谁负责）用 person→task 的普通边，不要建成依赖。
- **并行工作用 SS**：A 开始后 B 才启动（如"开发开始后对账体系并行跟进"）用 SS + lagDays，不要硬拆成两个串行 FS。
- **关键路径要能讲成一句话**：生成后跑 `validate_board.mjs`，链条应该是"契约测试 → 双写改造 → 灰度切换 → M2"这种可复述的主线；如果链条断碎或全是单点，说明依赖建模有问题。
- **日期口径**：startDate=可以开工的日期，dueDate=承诺完成日期；依赖导致的顺延应用会自动推演，不必手工压缩日期去"对齐"。
- **阻塞（blocker）是正在卡住的**：已有解决方案路径的写 task；真正卡死等外部条件的才建 blocker，并给 status: blocked。

## 风险登记册

- 风险写**事件**不写担忧："双写期间数据不一致"（好），"数据质量"（差）。
- 概率×影响要敢给高分：会造成资损/延期一周以上的影响给 high；概率按"是否已有缓解措施"倒推——还没措施的常见问题至少 medium。
- mitigation 必须是**可执行动作**，格式建议"检测手段 + 拦截/回退机制"："分钟级对账 + 一键回滚开关"（好），"加强监控"（差）。
- 高分风险（≥6）用普通边连到它威胁/缓解的任务上，label 写"威胁"或"缓解于"。

## vibe coding 项目（AI 结对开发）

- **状态机就是生成循环**：`in-progress`（AI 起草中）→ `in-review`（人工评审）→ `done`。评审打回改回 in-progress，不要跳步直接 done。
- **每个 AI 任务必写 `executor: 'ai'` 和 `acceptance`**：验收标准是 agent 的完成判据，写成可验证的一句（"E2E 三条链路在 CI 全绿"，好；"代码质量好"，差）。没有 acceptance 的 AI 任务校验器会提醒。
- **人机分工写进任务标题**："AI 起草：xxx" / "人工评审：xxx PR" / "验证门：xxx"，一眼看清谁干什么。
- **评审与验证是任务不是仪式**：评审任务给 `executor: 'human'`、验证门给 `executor: 'pair'`，都要有工时——它们是关键路径的一部分。
- **vibe coding 特有风险要登记**：上下文漂移改坏无关模块（缓解：任务切片小 + 单模块 PR + diff 全量评审）、生成代码安全漏洞（缓解：合并前扫描 + 密钥类代码人工写）、依赖幻觉（缓解：锁定版本 + 移除即失败）。
- **决策记录 AI 边界**：哪些交给 agent、哪些必须人写（密钥/支付/架构 token），用 ADR 固化，避免每个 PR 重新争论。

## 决策记录（ADR）

- 标题格式 `ADR-NN · 动词短语`：'ADR-01 · 以 Outbox 模式保证最终一致'。
- body 三段式：背景约束 → 结论 → 代价（被牺牲的选项说一句）。
- 还在对比的选型给 `proposed`，拍板的给 `accepted`；推翻旧决策时旧条目改 `superseded` 并新建 ADR，**不要删除历史**。
- 决策连到它的落地任务上，label 用"落地"。

## 工时与基线纪律（SPI/CPI 的数据质量）

- **每个任务必须有 `estimateHours`**：没有工时的任务不进加权进度，也会让 SPI/CPI 失真。估不准就给保守区间上界，宁可高估。
- **进行中任务每周更新 `actualHours` 与 `progress`**：AC 和 EV 都靠它们；只改状态不填工时，CPI 会虚高。
- **基线在计划冻结时设置**（WBS 概览「设为基线」）：此后改日期才会显示偏差。重大范围变更才允许清基线重设，并在决策记录里留一条 ADR 说明。
- 基线偏差 > 0 时先看关键路径上的偏差——非关键任务的顺延吃的是浮时，不必恐慌。

## 布局

- 空间视图按时间从左到右排布：文档/人物在最左，里程碑横贯顶部，任务链在中部，风险在下方，决策靠其影响对象。
- x 间隔 250–400，y 分层：里程碑 ~100、任务 330–700、风险 840+。
- 不要追求精确对齐——tilt 随机角就是这张"纸面"的气质。

## 生成后的自查清单

1. `node scripts/validate_board.mjs data.json` → 0 错误
2. 关键路径链条能读成一句话
3. 每个高风险都有 mitigation 且连到具体任务
4. 每个 accepted 决策都连到落地任务
5. 里程碑 ≤ 3 个；顶层任务 3–6 个（演示/模板场景）
